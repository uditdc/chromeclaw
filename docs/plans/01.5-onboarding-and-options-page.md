# 0.1.5 Onboarding and Options Page

## Overview

The options page is ChromeClaw's configuration hub — API key management, model selection, and preferences. It also serves as the landing page for first-time users via an onboarding flow that guides them through adding their first API key and choosing a default provider/model.

The side panel already has a model switcher and a chat interface, but there is no way to enter API keys. Without this, no LLM calls can succeed. This is the critical missing link.

## Architecture

**Options Page (`entrypoints/options/`)**: A React app rendered in a full Chrome tab (`chrome-extension://.../_generated_background_page.html`). WXT auto-registers it in the manifest when it detects the `options` entrypoint. Uses the same Tailwind setup and Zustand settings store as the side panel.

**Onboarding Flow**: On first open (no API keys stored), the options page renders a step-by-step wizard instead of the full settings UI. Steps: welcome → pick a provider → enter API key → verify key → done. After completion, a flag is written to `chrome.storage.sync` so the wizard doesn't show again. The side panel also checks this flag and shows a "Set up ChromeClaw" link if onboarding is incomplete.

**Settings Store (`stores/settings-store.ts`)**: Already provides `getApiKey()`, `setApiKey()`, `setActiveModel()`. The options page reads and writes through this store. The only addition is a `hasCompletedOnboarding` flag.

## File Structure

```
entrypoints/
  options/
    index.html                   -- WXT HTML entrypoint
    main.tsx                     -- React root mount
    App.tsx                      -- Router: onboarding wizard OR settings view
    style.css                    -- Tailwind import

components/
  options/
    ProviderSettings.tsx         -- API key input cards per provider, key validation
    ModelDefaults.tsx            -- Default provider/model selection
    OnboardingWizard.tsx         -- Step-by-step first-run setup
    ApiKeyInput.tsx              -- Single provider key input with show/hide and verify
```

## Implementation Steps

1. **Create options entrypoint** (`entrypoints/options/`): `index.html` with `manifest.type` set to `options_page`, `main.tsx` mounting React, `style.css` importing Tailwind. WXT will register this in the manifest automatically.
2. **Build `ApiKeyInput.tsx`**: A reusable component for a single provider. Shows the provider name, a password-type input with show/hide toggle, and a "Verify" button. On verify, sends a minimal API request to the provider (e.g., list models endpoint) and shows success/failure. Uses `settings-store.setApiKey()` to persist.
3. **Build `ProviderSettings.tsx`**: Renders an `ApiKeyInput` card for each provider from the `PROVIDERS` list in the settings store. Ollama gets a URL input instead of an API key. Shows a green check for providers with a stored key.
4. **Build `ModelDefaults.tsx`**: Dropdown selectors for default provider and model. Reads from and writes to the settings store. Only shows models for providers that have a configured API key.
5. **Build `OnboardingWizard.tsx`**: Multi-step wizard:
   - **Step 1 — Welcome**: Brief intro ("ChromeClaw needs an API key to get started"), list of supported providers.
   - **Step 2 — Provider & Key**: Pick a provider, enter the API key, verify it works.
   - **Step 3 — Done**: Confirmation, link to open the side panel.
   On completion, calls `completeOnboarding()` which sets `hasCompletedOnboarding: true` in `chrome.storage.sync`.
6. **Build `App.tsx` for options**: Check `hasCompletedOnboarding` on mount. If false, render `OnboardingWizard`. If true, render the full settings view (`ProviderSettings` + `ModelDefaults`).
7. **Extend `settings-store.ts`**: Add `hasCompletedOnboarding` state, `checkOnboarding()` (reads from `chrome.storage.sync`), and `completeOnboarding()` (writes flag). Hydrate on load alongside existing provider/model hydration.
8. **Add onboarding nudge to side panel**: In `entrypoints/sidepanel/App.tsx`, check `hasCompletedOnboarding`. If false, show a banner: "Welcome to ChromeClaw — [Set up your API key]()" that opens the options page via `chrome.runtime.openOptionsPage()`.
9. **API key verification**: All providers use the OpenAI-compatible protocol (`@ai-sdk/openai-compatible`), so verification is uniform — `GET {baseURL}/models` with the API key in the `Authorization: Bearer` header. For Ollama (no key required), just check connectivity. These calls run from the service worker (to avoid CORS) via a new `VERIFY_API_KEY` message type.

## Dependencies

- Feature 6.1 (settings store, side panel infrastructure)
- `chrome.storage.sync` for persisting keys and onboarding flag
- Zustand (existing store)

## Testing Strategy

- **Unit tests**: Test `ApiKeyInput` renders correctly, toggles visibility, calls `setApiKey` on save. Test onboarding flag read/write with mocked `chrome.storage`.
- **Integration tests**: Mock the verification API calls. Verify that entering a valid key shows success, invalid key shows error. Verify onboarding completion flag prevents the wizard from showing again.
- **E2E tests**: Load the extension fresh (no stored keys). Verify the options page shows the onboarding wizard. Complete the wizard. Verify the side panel no longer shows the setup banner. Open options again and verify the full settings view shows with the configured key.
